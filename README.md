# Avito Internship Fall 2025

Микросервис для автоматического назначения ревьюеров на Pull Request'ы.

## Запуск

```bash
make up
```

Сервис будет доступен на `http://localhost:8080`

Остановка:
```bash
make down
```

## API

### Команды

**Создать команду**
```bash
POST /team/add
```
```json
{
  "team_name": "backend",
  "members": [
    {"user_id": "u1", "username": "Alice", "is_active": true},
    {"user_id": "u2", "username": "Bob", "is_active": true}
  ]
}
```

**Получить команду**
```bash
GET /team/get?team_name=backend
```

### Пользователи

**Изменить активность**
```bash
POST /users/setIsActive
```
```json
{
  "user_id": "u1",
  "is_active": false
}
```

**Получить PR пользователя**
```bash
GET /users/getReview?user_id=u1
```

### Pull Requests

**Создать PR**
```bash
POST /pullRequest/create
```
```json
{
  "pull_request_id": "pr-001",
  "pull_request_name": "Add feature",
  "author_id": "u1"
}
```

При создании автоматически назначаются до 2 активных ревьюеров из команды автора.

**Merge PR**
```bash
POST /pullRequest/merge
```
```json
{
  "pull_request_id": "pr-001"
}
```

Идемпотентная операция - повторный вызов вернет текущее состояние.

**Переназначить ревьювера**
```bash
POST /pullRequest/reassign
```
```json
{
  "pull_request_id": "pr-001",
  "old_user_id": "u2"
}
```

Новый ревьювер выбирается случайно из активных участников команды заменяемого ревьювера.

**Стек:** Go 1.25, Gin, PostgreSQL 15

## Принятые решения

**Выбор ревьюеров**  
Ревьюверы выбираются случайно из доступных участников команды. Рассматривал варианты с round-robin или распределением по нагрузке, но для текущих требований это избыточно.

**Переназначение**  
При переназначении новый ревьювер ищется в команде того, кого заменяем, а не в команде автора. Так можно переназначать на людей из других команд.

**Идемпотентность merge**  
Если PR уже смержен, повторный запрос просто вернет его текущее состояние без ошибки.

**ID в виде строк**  
API использует строковые ID вместо чисел, как указано в OpenAPI спецификации. Это удобнее для UUID или читаемых идентификаторов.

**Пользователь в одной команде**  
При добавлении пользователя в новую команду через `/team/add`, он автоматически переходит туда из старой (upsert в БД).

**Деактивированные пользователи**  
Если пользователь деактивирован, он остается ревьювером на существующих PR. Просто больше не назначается на новые.

**Граничные случаи**
- Если активных участников меньше 2 - назначаем сколько есть
- Нет кандидатов для переназначения - ошибка `NO_CANDIDATE`
- Автор не существует - ошибка `NOT_FOUND`
